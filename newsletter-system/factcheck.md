# 발행 전 팩트체크 절차 (2026-08-29 도입)

원칙: **오정보는 한 건도 나가면 안 된다.** 아래 5단계를 모두 통과한 호만 푸시한다.
근거 사례: KADEX 2026을 4~5월 기사 기준으로 "10월 청주 개최"로 실었다가,
7월에 K-DEX로 통합된 사실을 사용자 지적으로 발견(발행 전 차단됨). 일정·조직은
몇 달 사이에도 바뀐다 — "한 번 확인한 사실"도 발행 시점에 다시 확인한다.

## 1. 링크 전수 검증
- 발행할 호의 JSON에서 모든 URL 수집 → 그날 원자료(raw)에 있는 URL은 수집 시점에
  실재했으므로 통과, 빌더가 조립한 URL(BUILT_URL_HOSTS: ted/sam/canadabuys 등)은
  전수 실접속(HEAD→GET) 확인.
- 실패 링크는 원자료의 정확한 URL로 교체 후 재생성. 실패 0건이 될 때까지.

## 2. 편집 주장 원문 대조 (해설 카드·제목)
- 해설 카드 제목, 제목 교정(daily_titles.json), 메일 제목의 **모든 사실 주장**을
  원문 기사(WebFetch)와 대조한다: 국가, 기관명, 수량·금액, 사업 단계(공고/낙찰/협상),
  행위(환영했다/계약했다/검토한다)의 강도.
- 원문이 말하지 않는 것을 제목에 넣지 않는다. 추측성 보도는 "~설", "~로 알려졌다"로
  한 단계 낮춰 표기하고 C등급 이하.
- 아티클 스크랩은 "원문 제목의 번역"이므로 별도 대조는 생략하되, 번역이 원제와
  반대 의미가 되지 않았는지 표본 점검(상위 5건).

## 3. 일정 데이터 최신성 검증 (전시회·세미나)
- 발행일 기준 **D-60 이내** 행사 전건: "행사명 + postponed/cancelled/연기/취소/통합/변경"
  웹 검색으로 변동 확인. 주최측 공식 사이트가 있으면 날짜를 직접 재확인.
- D-60 밖 행사는 **주 1회(월요일 주간호 발행 시)** 전체 롤링 점검.
- 새 행사 추가 시: 공식 사이트 또는 2개 이상 언론 보도로 날짜·장소 확인 전에는
  dated에 넣지 않는다(정례/미확정 목록에 둔다). 집계 사이트(10times 등)는 근거로 쓰지 않는다.

## 4. 수치 검증
- 리드·요약·부제의 건수(신호 N건, 공고 N건)는 코드가 데이터에서 계산한 값만 사용.
  수기로 숫자를 적지 않는다.
- 서로 다른 출처의 수치가 상충하면 "확정되지 않았다"고 쓰고 C등급.

## 5. 기록
- `data/factcheck/{발행일}.md`에 검증 대상·방법·결과·수정 내역을 남긴다.
- 형식: 항목 / 확인 방법 / 결과(✓·수정·보류) 한 줄씩.
